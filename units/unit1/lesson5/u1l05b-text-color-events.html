reach for it when

The new thing

Your program can say something


fill(120, 220, 140);
textSize(24);
text("ALTITUDE", 20, 40);
text(what, x, y) — the words, then where they go. Same two numbers as everything else.
x, y is the bottom left of the words Not the top. Put it at y = 0 and it is off the screen.
FOUR MINUTES. Four presses. THE COLOR COMES FROM fill(). Same setting as shapes - fourth example this unit. Say "same rule" and move on. textSize() is the only new setting and it needs no explanation. THE CALLOUT IS THE PRACTICAL TRAP. The y is the BASELINE - the bottom of the letters, not the top. text("HI", 20, 0) draws above the canvas and is invisible. Someone will do it. Do not teach textAlign or textFont today. They exist, they are in the reference, they are not the lesson.
Quotes change what a thing is

These two lines are not the same


text(landerY, 20, 40);
text("landerY", 20, 80);
Without quotes, landerY is a variable — you get what is in it.
With quotes it is a string — the characters themselves, nothing more.
Joining them text("ALT " + landerY, 20, 40)
THREE MINUTES, AND THIS IS THE MISCONCEPTION OF THE LESSON. A STRING IS A NEW KIND OF VALUE. Everything so far has been a number. A string is characters, in order, and the quotes are what make it one. ASK BEFORE PRESSING: "what does the second line put on the screen?" Someone will say 210. It says the word landerY. "200" AND 200 ARE DIFFERENT THINGS. Worth one sentence. You cannot do arithmetic on the first one - "200" + 1 gives "2001", because joining is what + does to strings. Show it if someone asks; do not go looking for it. THE PLUS SIGN JOINS STRINGS. That is called concatenation and it is CED topic 3.4. They need it for the readout in five minutes, so teach it as a tool, not a topic.

One more kind of value

A variable can hold a color


let hullColor = color(214, 222, 235);

fill(hullColor);
rect(200, 195, 60, 90);
color() takes the same numbers as fill() — three for RGB, one for gray, four with alpha.
Why bother Change the hull color in one place instead of six.
THREE MINUTES, AND THIS IS THE FIRST CUT IF YOU ARE BEHIND. It is on the reference sheet either way. THE POINT IS NOT color() - it is that a variable holds more than numbers. Numbers, strings, colors. The CED lists numbers, Booleans, lists and strings as the types; color is p5's own, and saying so is honest. THE CALLOUT IS THE REAL ARGUMENT and it is the second reason for variables from Lesson 4B: the same value in several places. Six shapes share a hull color; one variable changes all six. Do not go into color objects or brightness. Not today, not this year.
The other new thing

Code that runs when something happens


function keyPressed() {
  headY = 90;
}

runs once, when a key goes down


function mousePressed() {
  speed = 0;
}

runs once, when the mouse is clicked

These sit beside draw(), not inside it draw() runs sixty times a second, whatever happens. These run only when the thing happens.
FOUR MINUTES. THEY ALREADY KNOW WHAT A FUNCTION LOOKS LIKE - setup() and draw() have been on every sketch since Lesson 1. These are two more of the same shape. Say that; it is less new than it looks. THE CALLOUT IS THE STRUCTURAL POINT and students get it wrong by nesting them inside draw(). Draw them on the board as three separate blocks, side by side, all at the same level. NAMES ARE FIXED. p5 looks for exactly keyPressed and mousePressed. A capital letter in the wrong place and nothing happens, with no error. Same silent failure as the = trap. If someone asks how to tell WHICH key: the variable is called key, and it is a string. Mention it only if asked - one key doing one thing is enough today.
Together · back to the robot

A key that puts it back


function draw() {
  headY = headY + 1;
}

function keyPressed() {
  headY = 90;
}
One line resets everything Every part follows headY, so putting it back puts the whole robot back.
FOUR MINUTES. Same sketch. Add the function below draw(), run it, hold a key. THE CALLOUT IS THE PAYOFF FOR LESSON 4A. Because every part of the robot is an offset from headY, resetting one variable resets the whole thing. A robot built with fixed numbers could not be reset at all. NAME IT: this is the RESET PATTERN - a handler that puts several variables back to their starting values. It comes back in Unit 5 when they refactor, and again in the Create task. Patterns they can name are patterns they can reuse. HOLD THE KEY DOWN and it fires repeatedly - that is the operating system repeating the key, not p5. Worth ten seconds if someone notices. ASK: what would you add to also reset the speed? Nothing yet - speed is still a literal 1 in draw(). That is a good thing to notice and it points at the rocket task.

On your board · 4 minutes

Write the two handlers


let x = 50, y = 100, r = 50;
let speed = 0;

function draw() {
  background(220);
  circle(x, y, r);
  x = x + speed;
  r = r + speed / 5;
}
  1. Any key → speed goes up by 3
  2. Mouse → everything goes back to the start
function keyPressed() {
  speed = speed + 3;
}

function mousePressed() {
  x = 50; y = 100;
  r = 50; speed = 0;
}
FOUR MINUTES, AND THIS IS THE SECOND CUT IF YOU ARE BEHIND. Groups write both functions. Nothing is running - this is reading a spec and producing code, which is the harder direction. THE FIRST ONE catches anyone who writes speed = 3 instead of speed = speed + 3. The spec says "goes up by 3", not "becomes 3". Press a key twice and the difference shows. THE SECOND ONE is four assignments and the easy one to under-answer - boards that reset x and y but forget r and speed. Ask what "back to the start" includes. Reveal both at once and let them compare.

TWO MINUTES. The exam has no canvas, so DISPLAY takes one thing and shows it. Everything about position is p5's, not the exam's. Exam questions very often end with a DISPLAY and ask what appears.
